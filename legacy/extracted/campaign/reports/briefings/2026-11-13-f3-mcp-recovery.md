# F3: зависимость от MCP устранена; продолжение заблокировано ответом провайдера

**Ошибка обязательного `mcp__searcharvester__search` устранена в новой конфигурации F3. Само доказательство пока не продолжилось: первый запрос из CLI получил OpenAI 403 `unsupported_country_region_territory`.** Повторять этот невременный отказ или менять endpoint/прокси для его обхода не стали. Нельзя считать задачу полностью восстановленной.

## Причина предупреждения

В pi-extensible-workflows 6.3.0 `host.ts` сохраняет в snapshot весь root tool ceiling, а `resumeLaunchPrologue` требует присутствия каждого инструмента. Исходный F3 сохранил 234 инструмента, включая неиспользуемые MCP-сервисы. Родительская сессия подключает MCP асинхронно; проверка до готовности реестра способна дать показанное предупреждение. Точный порядок событий прежнего старта не инструментировался: временная неготовность — обоснованное объяснение, не доказанная трасса того старта.

В текущей сессии поддержанная MCP discovery дождалась инструментов. Один реальный search-вызов вернул результат без isError, и все 234 прежних инструмента теперь представлены. Само присутствие инструмента в каталоге было дополнено реальным вызовом, а не выдано за проверку работоспособности.

Выявлено и второе ограничение: новое выполнение `tools.write` после UI Resume не поддерживается без контекста вызова инструмента. Исходный скрипт использовал такие записи. Поэтому повторный Resume из меню не был принят как достаточное решение.

## Что исправлено

Использован уже установленный официальный @piewf/cli 6.3.0; глобальные пакеты, конфиги MCP, endpoints и прокси не менялись. Это тот же Pi, не миграция платформы.

- Три безагентных canary подтвердили запуск без MCP и поддержку `evidence()`/`shell()`, включая сохранение фаз.
- Новый `scripts/ogu-aro-formal-v3-offline-continuation.workflow.js` не содержит session-tool calls; фазовые результаты сохраняются через поддержанные durable host operations.
- Root snapshot нового реального запуска содержит 11 инструментов и **0 MCP**. Агенту разрешены только `read`, `bash`, `edit`, `write`.
- В начале workflow есть машинный барьер: если root snapshot неожиданно содержит MCP, математические агенты не запускаются.
- Воспроизводитель на установленном `reachableTools` показывает исходную ошибку для MCP-pending inventory и её отсутствие для нового реального snapshot даже без MCP.

Проверка:

```
node artifacts/workflow-recovery/f3-mcp/reproduce.mjs
```

Результат: исходный pending inventory → `Required tool is unavailable: mcp__searcharvester__search`; исправленный snapshot → `fixedSnapshotMcpTools: 0`, `fixedSnapshotWorksWithPendingMcp: true`.

Сам установленный extension не патчился: его общая хрупкость root snapshot/startup остаётся upstream-проблемой. Исправление здесь убирает ненужную зависимость из конкретного формального процесса.

## Сохранность и реальные исходы

Исходный запуск `8d7a9e60-882c-4e89-8a58-429e7f62771f` сначала проверен как interrupted, затем остановлен штатным workflow_stop. Журнал/snapshot вручную не редактировались. Все 55 файлов незавершённого ревью сохранены и привязаны хешами. Новая версия не объявляет это ревью принятым и не меняет математические цели, модели или доказательства F1/F2.

Новый запуск: `e5abeb96-418f-4684-a43d-84e81d9d71bd`, `aro-ogu-to-aro-formal-v3-offline-continuation`. Он прошёл zero-MCP gate и compiler preflight, но первый агент получил `AGENT_FAILED` с OpenAI HTTP 403 `unsupported_country_region_territory`. По telemetry ни одного успешного ответа модели нет; фактический billing неизвестен. Это не ошибка Lean, не математический контрпример и не transient-сбой.

Supervisor завершился с CLI exit 1, disk reserve не нарушен; ненужных новых фоновых процессов не оставлено. Подтверждённое состояние workflow — failed. Свидетельства: `artifacts/workflow-recovery/f3-mcp/offline-host/`, включая capability-check.json и completion.json.

Read-only сравнение присутствия/хешей HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/OPENAI_BASE_URL/PI_CODING_AGENT_DIR/PI_OFFLINE не выявило различий маршрутизационных переменных между shell и текущим workflow-host. Это не полный аудит auth/provider context; причиной регионального отказа различие этих переменных не объявляется. Секреты не выводились и не менялись. Что именно вызвало региональное ограничение, не установлено.

## Следующий разрешённый шаг

Нужна действующая, разрешённая конфигурация доступа к OpenAI в используемом режиме. После устранения причины отказа со стороны легитимного доступа новый failed run можно восстановить штатным workflow_retry с expectedState=failed; у него уже нет MCP-зависимостей и UI-tool-context проблемы. Сейчас повтор не выполнялся, fallback модели/провайдера не запускался. Обход регионального ограничения не предлагался.

F1/F2 сохраняют прежние проверенные доказательства; F3/F4 и весь мост остаются незавершёнными. Коммитов/пушей, научных переходов статуса и аттестации нет.
