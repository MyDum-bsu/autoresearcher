Notation normalization used below: two-stage problem
`min_{x∈X} max_{u∈U} min_{y∈Y(x,u)} a^T x + b^T y` with `Y(x,u) = {y : Ax+By+Cu ≥ c, y ≥ 0}`;
`X ⊆ R^{n1} × Z^{n2}` (mixed-integer first stage), `y ∈ R^m` continuous recourse;
`U = {u ∈ R^l : Du ≤ d, u ≥ 0}` polytope (their bold `\a,\b,\A,\B,\C,\c,\D,\d`).
`Z̲(x,{u}) = min_{y∈Y(x,u)} b^T y`; `Z̄(x) = a^T x + max_{u∈U} Z̲(x,{u})`; `ū(x)` a maximizer;
`Z̃(x)`, `ũ(x)` — the complementarity-based oracle of Proposition 1;
`W = {w ∈ R^r : w ≥ 0, B^T w ≤ b}` (dual uncertainty / wedge);
`F1` = fast (inexact) feasibility oracle, `F2` = exact feasibility oracle;
DBC = Dual Basis Cuts algorithm with partitions `{W^p}` of `W` and linear rules
`λ^p(w) = Z^p w + z^p`.

## Theorem blocks

### thm-prop-1: Complementarity-slackness optimality oracle (Prop. prop:CCG_equiv)
- statement: If `x ∈ X` is feasible (`Z̄(x) < ∞`), then the adversarial upper-bound problem
  and the complementarity-based problem are equivalent: `Z̄(x) = Z̃(x)`, where
  `Z̃(x) = a^T x + max { b^T y : u ∈ U, y ≥ 0, w ≥ 0, Ax+By+Cu ≥ c, B^T w ≤ b,
  w^T(Ax+By+Cu−c) = 0, y^T(b−B^T w) = 0 }`, with the same optimal solution set.
  The two bilinear equalities are reformulable as `r+m` SOS-1 constraints or via big-M
  with `r+m` binary variables (their eq. 8).
- conditions: linear two-stage structure (eq. 1); problem bounded; `x` feasible. The
  oracle is invalid for infeasible `x` (see thm-prop-3).
- anchor: DDBD_ver4_forArxiv.tex:373-374 — `If $\bx\in X$ is a feasible solution to Problem \eqref{eq:2stage_robust}, \ie $\overline{Z}(\bx)<\infty$, then  Problems  \eqref{eq:SecondStage_UpperBound} and \eqref{eq:SecondStage_WorstCaseCost} are equivalent, \ie` / `$\overline{Z}(\bx)=\tilde{Z}(\bx)$ and they have the same optimal solution set.`
- our-relevance: this is the paper's LP/complementarity certificate machinery for exact
  adversarial evaluation — the same CS/Big-M gate structure our condition-(B)-style
  optimality certificates use, and the finite-certificate logic behind any
  full-information formula (including our 2D wedge-W problem).

### thm-prop-2: CCG finite convergence under relatively complete recourse (Prop. prop:CCG_converge)
- statement: Let Assumption 1 (relatively complete recourse) hold and let CCG use the
  oracle `(Z̃, ũ)`. If `U` is convex and `U, X` are compact, every limit point of `{x^k}`
  is optimal. If alternatively `U` is a polytope, `ū(x)` can always be chosen a vertex of
  `U`, and CCG terminates in finitely many steps.
- conditions: Assumption 1 (relatively complete recourse, stronger than feasibility);
  CS-based oracle of thm-prop-1; compactness (or polytope `U`).
- anchor: DDBD_ver4_forArxiv.tex:432-433 — `\begin{proposition}[Extension of {\citep[Proposition 2]{Zeng2013}}]\label{prop:CCG_converge}` / `If $U$ is convex, and both $U$ and $X$ are compact, then any limit point of the sequence $\{\bx^k\}_{k\in\mathbb{N}}$ is an optimal solution of Problem~\eqref{eq:2stage_robust}.  If alternatively $U$ is a polytope, then $\overline{\bu}(\bx)$ can always be chosen to be a vertex of $U$, and Algorithm~\ref{alg:CCG} terminates in a finite number of steps.`
- our-relevance: baseline finite-convergence template (vertex generation + bound
  tightening) that our constraint-generation / LP-certificate loops imitate; explicitly
  framed as an extension of Zeng-Zhao 2013, Proposition 2.

### thm-prop-3: CCG breakdown under mere feasibility (Prop. prop:CCG_Limitation)
- statement: Let `x^k` be generated by CCG using `(Z̃, ũ)`. If `x^k` is infeasible
  (`Z̄(x^k) = ∞`), then `Z̃(x^k) < Z̄(x^k)` (the oracle underestimates the adversarial
  value). Moreover, if `U` is a polytope, a maximizer `ũ(x^k)` that is a vertex of `U`
  need not exist — the CS-oracle's maximizers are vertices of the lifted polytope
  `{(u,y) : Ax^k+By+Cu ≥ c, Du ≤ d}`, not of `U`. Hence CCG may fail to converge or
  converge to an infeasible first-stage decision.
- conditions: only Assumption 2 (feasibility) holds; CS-oracle used outside its validity
  domain (infeasible `x`); polytope `U`.
- anchor: DDBD_ver4_forArxiv.tex:439-440 — `If $\bx^k$ is not feasible ($\overline{Z}(\bx^k)=\infty$), then $\tilde{Z}(\bx^k)<\overline{Z}(\bx^k)$.` / `Moreover, if $U$ is a polytope, then there does not necessarily exist a $\tilde{\bu}(\bx^k)$ that is a vertex of $U$.`
- our-relevance: the precise failure mechanism (silent truncation of the adversary's
  feasible set) when a condition-(B)-style feasibility profile replaces relatively
  complete recourse — a warning for any solver loop of ours that reuses optimality
  oracles as feasibility oracles.

### thm-prop-4: CCG converges with an exact feasibility oracle (Corollary, §2.2)
- statement: Define `Z̄(x) = ∞` if `ᾱ(x) > 0` and `Z̃(x)` otherwise, and
  `ū(x) = u^α(x)` if `ᾱ(x) > 0` and `ũ(x)` otherwise, where
  `ᾱ(x) = max_{u∈U} α̲(x,u)` is the worst-case L1-feasibility value (fact-prop-5).
  Under Assumption 2 (feasibility), if `U` is a polytope, CCG terminates finitely and
  returns an optimal solution.
- conditions: Assumption 2 (mere feasibility); the hybrid worst-case definition
  (eqs. 15–16); polytope `U` (vertex generation preserved via fact-prop-3).
- anchor: DDBD_ver4_forArxiv.tex:494-495 — `Let \eqref{eq:RealWorstCase} and \eqref{eq:RealWorstCase_Realization} be used to compute $\overline{Z}(\cdot)$ and $\overline{\bu}(\cdot)$, respectively, in Algorithm~\ref{alg:CCG}, and let Assumption~\ref{ass:feasibility} hold.` / `If $U$ is a polytope, then $\overline{\bu}(\bx)$ can always be chosen as a vertex of $U$, and Algorithm~\ref{alg:CCG} terminates in a finite number of steps with an optimal solution for Problem \eqref{eq:2stage_robust}.`
- our-relevance: shows the weaker condition-(B) profile (feasibility without relatively
  complete recourse) still admits exact finite algorithms once feasibility certificates
  are made first-class — the structural template for our feasibility-gated solver loops.

### thm-prop-5: DDBD finite convergence (main theorem, §3)
- statement: Let `F1` be a fast oracle returning `u^F(x)` with
  `Z̃(x) ≤ Z̲(x,{u^F(x)}) ≤ Z̄(x)` (and a vertex of `U` if `U` is a polytope), and `F2`
  an exact feasibility oracle that verifies `x` and, if infeasible, returns
  `ū(x)` with `Z̄(x) = Z̲(x,{ū(x)})` (w.l.o.g. a vertex). Under Assumption 2, if `U` is
  a polytope, DDBD (Algorithm 2: F1-driven bound loop, F2 verification only at the end)
  terminates in finite steps and returns an optimal solution.
- conditions: Assumption 2 (feasibility); the two-oracle contract above; polytope `U`;
  proof "similar to that of Proposition prop:CCG_converge" (omitted, line 537).
- anchor: DDBD_ver4_forArxiv.tex:534-535 — `Let $\mathcal{F}_1$ and $\mathcal{F}_2$ be the fast and exact feasibility oracles in Algorithm~\ref{alg:DDBD}, respectively, and let Assumption~\ref{ass:feasibility} hold.` / `If $U$ is a polytope, then Algorithm~\ref{alg:DDBD} terminates in a finite number of steps and return an optimal solution of Problem~\eqref{eq:2stage_robust}.`
- our-relevance: the paper's headline result — a cheap-heuristic + expensive-exact-
  certificate architecture that preserves exactness under condition-(B); a direct
  blueprint for budget-aware certificate scheduling in our LP-based solvers.

### thm-prop-6: Fast oracle guarantee via alternating maximization (Prop., §4.1)
- statement: Let `u^F(x)` be the output of the Alternating Maximization (AM) heuristic on
  the bilinear infeasibility detector
  `max { (c−Ax−Cu)^T w : u ∈ U, B^T w ≤ 0, 0 ≤ w ≤ 1 }` (their eq. 20, started at `ũ(x)`).
  Then `Z̲(x,{u^F(x)}) ≥ Z̲(x,{ũ(x)}) = Z̃(x)`; and if `U` is a polytope, `u^F(x)` can be
  chosen a vertex. By thm-prop-1, if `x` is feasible then `Z̲(x,{u^F(x)}) = Z̄(x)`
  (line 504); AM terminating with a nonpositive value only means infeasibility is
  unproven, not that `x` is feasible.
- conditions: AM initialized at `ũ(x)`; `U` convex compact for convergence of AM;
  polytope `U` for the vertex claim; heuristic — no global optimality guarantee.
- anchor: DDBD_ver4_forArxiv.tex:587-588 — `$$\underline{Z}(\bx,\{\bu^{\mathcal{F}}(\bx)\})\geq \underline{Z}(\bx,\{\tilde{\bu}(\bx)\})\equiv\tilde{Z}(\bx).$$` / `If $U$ is a polytope then $\bu^{\mathcal{F}}(\bx)$ can always be chosen as a vertex of $U$.` (contract with exactness on feasible `x`: line 504 — `such that $\tilde{Z}(\bx)\leq \underline{Z}(\bx,\{\bu^{\mathcal{F}}(\bx)\})\leq \overline{Z}(\bx)$. It follows from Proposition \ref{prop:CCG_equiv} that if $\bx$ is feasible then $\underline{Z}(\bx,\{\bu^{\mathcal{F}}(\bx)\})= \overline{Z}(\bx)$.`)
- our-relevance: a one-sided certificate pattern (positive AM value ⇒ certified
  infeasibility; zero ⇒ no conclusion) — exactly the sound-cheap vs exact-expensive
  layering our LP budget/certificate design has to reason about.

### thm-prop-7: Infeasibility certificate from a basis-optimal partition (Prop., §4.2)
- statement: In DBC, if at some stage `τ* = ∞` and there exists an active partition
  `p ∈ A` with partition index `ℓ^p = 0` (an element on which the optimal dual policy is
  already exactly the basis policy `λ(w) = −D̃_{I^p}^{-1} C^T w`), then `x` is infeasible.
  The matching unbounded ray `w̃` is obtained from
  `argmax { (c−Ax+(Z^p)^T d)^T w : B^p w ≤ 0, 0 ≤ w ≤ 1 }` (their eq. 26), and then
  `ū(x) ∈ argmax_{u∈U} (c−Ax−Cu)^T w̃`.
- conditions: dual formulation (fact-prop-6); basis-based partitioning of
  `W = {w ≥ 0 : B^T w ≤ b}`; `τ^p` unbounded on a primary (non-further-split) element.
- anchor: DDBD_ver4_forArxiv.tex:664-665 — `If at some stage of Algorithm~\ref{alg:Dcuts}, for which $\tau^*=\infty$, there exists a partition $p\in\mathcal{A}$ with partition index $\ell^p=0$, then $\bx$ is infeasible for Problem~\eqref{eq:2stage_robust}.` (ray extraction: lines 705-708 — `\tilde{\bw}\in\argmax_{\bw:\bbb^p\bw\leq 0,0\leq\bw\leq 1} (\bc-\bba\bx+(\bbz^p)^T\bd)^T\bw,` / `which is guaranteed to be positive (since the problem is unbounded on this partition).`)
- our-relevance: an exact, finitely checkable infeasibility certificate read off the
  piecewise-linear structure of `λ*(w)` over the dual wedge `W` — the same wedge
  geometry as our published full-information formula for the 2D guaranteed-control
  problem; the certificate is a plain LP (ray + maximizer), i.e. squarely an
  LP-certificate object.

### thm-prop-8: DBC finite termination (Theorem, §4.2)
- statement: DBC terminates after finitely many iterations. The partition tree has depth
  `h` bounded by the number of feasible bases, `h ≤ 2^{d+l}` (bases are not reused along
  an ancestor chain), hence the iteration count obeys `K ≤ (d^{2^{d+l}} − 1)/(d − 1)`.
- conditions: polytope `U`; each DBC step sub-partitions active unbounded elements via a
  new optimal basis; `d` rows of `D`, `l` uncertainty dimensions.
- anchor: DDBD_ver4_forArxiv.tex:736 — `Algorithm~\ref{alg:Dcuts} will terminate after a finite number of iterations.` (bound from the proof, lines 740-741 — `The number of feasible bases is bounded above by ${{d+l}\choose{l}}\leq {2^{d+l}}$. Thus, we have that` / `$h\leq {2^{d+l}}$ and $K\leq \frac{d^{2^{d+l}}-1}{d-1}$ is finite.`)
- our-relevance: the only quantitative guarantee offered is doubly exponential and
  vacuous in practice — leaves open tight, instance-typical certificate-count bounds,
  which is precisely where our exactness/cost analysis could contribute.

## Fact blocks

### fact-prop-1: Problem class covered
- statement: Linear two-stage adaptive problem
  `min_{x∈X} max_{u∈U} min_{y ∈ R^M: Ax+By+Cu ≥ c, y ≥ 0} a^T x + b^T y` with mixed-integer
  first stage `x ∈ X ⊆ R^{n1} × Z^{n2}`, continuous recourse `y`, and polytope
  `U = {u ∈ R^l : Du ≤ d, u ≥ 0}`; problem assumed bounded.
- anchor: DDBD_ver4_forArxiv.tex:219 — `\min_{\bx\in X}\max_{\bu\in U} \min_{\by\in \real^M:\bba\bx+\bbb\by+\bbc\bu\geq \bc, \by\geq 0} \ba^T\bx+\bb^T\by,` and line 226 — `\paren{\bu\in \real^{l}:\bbd\bu\leq \bd, \bu\geq\bzero},`
- applies: two-stage adaptive linear optimization with polyhedral uncertainty, continuous
  recourse, possibly integer first stage.

### fact-prop-2: Two-tier feasibility assumptions (A vs B)
- statement: Assumption 1 "Relatively complete recourse": `Y(x,u) ≠ ∅` for any `x ∈ X`,
  `u ∈ U`. Assumption 2 "Feasibility": there exists `x ∈ X` with `Y(x,u) ≠ ∅` for all
  `u ∈ U`. Assumption 2 is strictly more general; the source labels assumptions
  alphabetically (line 78), i.e. A and B.
- anchor: DDBD_ver4_forArxiv.tex:241 — `There exists $\bx\in X$ such that for any $\bu\in U$ the set  $Y(\bx,\bu)\neq \emptyset$.` and line 243 — `Thus, it is clear that Assumption~\ref{ass:feasibility} is more general than Assumption~\ref{ass:full recourse}.`
- applies: the whole paper; CCG results need A (or an oracle), DDBD needs only B.

### fact-prop-3: Worst case attained at an extreme point
- statement: If `x ∈ X` is feasible and `U` is compact, a worst-case realization `ū(x)`
  exists and can be chosen as an extreme point of `U` (proof: strong duality + linear
  maximization over `U` attains at an extreme point).
- anchor: DDBD_ver4_forArxiv.tex:420 — `Let $\bx\in X$ be a feasible solution to Problem~\eqref{eq:2stage_robust}. If $U$ is a compact set, then there always exists $\overline{\bu}(\bx)$ which is an extreme point of $U$.`
- applies: feasibility side of any two-stage problem with compact `U`; the engine of all
  finite-convergence arguments here.

### fact-prop-4: Adversarial problem is NP-hard
- statement: Even for a feasible `x`, computing `Z̄(x)` and `ū(x)` is NP-hard.
- anchor: DDBD_ver4_forArxiv.tex:360 — `In general, even for a feasible $\bx$ (such that $Y(\bx,\bu)\neq \emptyset$ for any $\bu\in U$), computing $\overline{Z}(\bx)$ and $\overline{\bu}(\bx)$ is NP-Hard.`
- applies: general two-stage linear adaptive problems; justifies MIO/heuristic oracles.

### fact-prop-5: L1 relaxation turns feasibility into a recourse problem
- statement: `Y(x,u) ≠ ∅` iff the LP `α̲(x,u) = min { α : α ≥ 0, y ≥ 0, Ax+By+Cu+α·1 ≥ c }`
  has optimal value 0. The lifted problem (variables `(y,α)`) satisfies relatively
  complete recourse, so thm-prop-1 applies to it: `x` is feasible iff `ᾱ(x) = 0`, and the
  maximizer `u^α(x)` can be chosen an extreme point of `U`. Practical caveat: the MIO
  computing `ᾱ(x)` "does not solve even after 20-30 minutes" on their instances.
- anchor: DDBD_ver4_forArxiv.tex:471-472 — `\underline{\alpha}(\bx,\bu)=&\min_{(\alpha,\by)\in\real_+\times\real^m_+} \alpha\\` / `&\text{s.t.} &\bba\bx+\bbb\by+\bbc\bu+\alpha \bone\geq \bc.` ; line 479 — `\item $\bx$ is feasible if and only if $\overline{\alpha}(\bx)=0$.` ; line 498 — `the optimization problem used to compute $\overline{\alpha}(\bx)$, for the same problem instance, does not solve even after 20-30 minutes.`
- applies: feasibility checking under Assumption 2 (B); the naive exact certificate is
  LP/MIO but computationally fragile.

### fact-prop-6: Two-stage robust dual; λ*(w) is piecewise linear, x-independent
- statement: The problem admits the dual formulation
  `min_{x∈X} a^T x + max_{w∈W} min_{λ ≥ 0 : C^T w + D^T λ ≥ 0} (C−Ax)^T w + d^T λ` with
  `W = {w ∈ R^r : w ≥ 0, B^T w ≤ b}`. Here `x` affects only the objective, not
  feasibility; for fixed `w` the optimal `λ` solves an LP independent of `x`; writing the
  inner LP in standard form with `λ̃, d̃ = [d; 0], D̃ = [D, −I]`, for any optimal basis `I`:
  `λ̃*_I = −D̃_I^{-1} C^T w` is optimal on the region
  `W_I = {w ∈ W : −D̃_I^{-1} C^T w ≥ 0}`. Hence the optimal dual policy `λ*(w)` is
  piecewise linear in `w` and independent of `x`.
- anchor: DDBD_ver4_forArxiv.tex:619 — `&\min_{\bx\in X} &\ba^T\bx+\max_{\bw\in W}\min_{\blambda\geq 0:\bbc^T\bw+\bbd^T\blambda\geq 0} (\bc-\bba\bx)^T\bw &+\bd^T\blambda,\\` ; line 622 — `where $W=\paren{\bw\in\real^r: \bw\geq0,\bbb^T\bw\leq \bb}$.` ; lines 640-641 — `$\tilde{\blambda}_I^*=-\tilde{\bbd}_I^{-1}\bbc^T\bw$, and this basis is optimal for all $\bw$ which belong to` / `$$W_I=\paren{\bw\in W:-\tilde{\bbd}_I^{-1}\bbc^T\bw\geq \bzero}.$$ Thus, it follows that the optimal $\blambda(\bw)$ is a piecewise linear function of $\bw$, and independent of $\bx$.`
- applies: the dual side of any two-stage linear adaptive problem (dual from
  Bertsimas-de Ruiter 2016, cited key `Bertsimas2015`); `W` here is exactly a wedge-type
  dual uncertainty set.

### fact-prop-7: Alternating maximization convergence behavior
- statement: AM on the bilinear objective is monotone; for convex compact `U` the value
  converges to a limit in sublinear time and all limit points are stationary points; but
  there is no guarantee of reaching the true optimal value.
- anchor: DDBD_ver4_forArxiv.tex:580-581 — `We know, by the fact that the AM method is monotone and that the objective function is continuous (specifically bilinear), that if $U$ is convex and compact, then the value will converge to some limit in sublinear time (see for example \citep[Theorem 10]{shtern2016computational}), and that all` / `limit points of the algorithm are stationary points of the problem \citep[Corollary 2]{Grippo2000}. However, there is no guarantee that the AM method will converge to the true optimal value.`
- applies: the `F1` heuristic inside DDBD (bilinear feasibility detector).

### fact-prop-8: Empirics — ADR often (near-)optimal; CCG routinely infeasible
- statement: In the location-transportation experiments, the affine decision rule is
  reported optimal or close to optimal. CCG converged to an infeasible solution in 31%
  of location-transportation and 34% of lot-sizing instances (intro summary: "more than
  30%"), and to an infeasible solution in all unit-commitment scenarios; DDBD always
  returned feasible (hence optimal, after verification) solutions.
- anchor: DDBD_ver4_forArxiv.tex:783 — `We found that, for this problem and under this choice of parameters (as well as many others), the affine decision rule is often optimal or close to optimal. This therefore raises the question of how fast does the algorithm detect that this is the case.` ; line 785 — `We see that for $31\%$ of the instances tested the CCG algorithm converged to an infeasible solution, while the DDBD always converged to a feasible solution without the need to utilize Step 4 of Algorithm~\ref{alg:DDBD}.` ; line 845 — `we see that in $34\%$ of the instances the CCG algorithm terminated with an infeasible solution.`
- applies: the three tested classes (location-transportation, capacitated network
  lot-sizing, unit commitment IEEE-14).

## Open threads for our portfolio
- ADR exactness is observed but unexplained: the paper explicitly leaves open "how fast
  does the algorithm detect that this is the case" that the affine rule is optimal
  (anchor: DDBD_ver4_forArxiv.tex:783) — direct empirical fuel for conj-ldr-exactness;
  no theory of when ADR is exact is given or attempted.
- Dual-side exactness vs primal-side gap: on the dual side the exact policy `λ*(w)` is
  piecewise linear and linear on each optimal-basis region `W_I`
  (anchor: 640-641), i.e., partitioned linear rules are exact there once partitions align
  with bases; no analogous statement exists for the primal `y(u)`. Our exactness
  conditions for affine rules should distinguish the two sides — the wedge-W
  full-information formula we already have lives on this dual side.
- Exact feasibility verification is the bottleneck: verification took 168/364/12443 s
  for T=6/12/24 vs optimality times 19/46/375 s (anchor: 925, table row line 943
  `24 & 375 & 5& 12443& 1\\`), and the naive `ᾱ(x)` MIO certificate does not solve in
  20-30 min (anchor: 498). Cheaper condition-(B)-style feasibility certificates (LP
  budget/certificates) remain open — including for wedge-type 2D guaranteed-control
  problems where basis enumeration is tiny.
- No criterion for trusting F1: in all unit-commitment runs F2 was never needed
  (anchor: 925 `However, in all cases there was actually no need to run $\mathcal{F}_2$ to verify feasibility, since the optimal solution was indeed obtained, and no feasibility cuts were added.`),
  but the paper offers no test for when AM's nonpositive value may be trusted as
  feasibility proof — a false-accept risk our certificate budget analysis could
  quantify.
- The only termination bound is doubly exponential, `K ≤ (d^{2^{d+l}} − 1)/(d − 1)`
  (anchor: 741); typical-case partition counts and tighter bounds are open.
- Mixed-integer first stage is handled algorithmically only (`X ⊆ R^{n1} × Z^{n2}`,
  anchor: 222); convergence carries over, but no exactness/quality theory interacts with
  integrality — relevant if our condition-(B) lines ever touch integer first stages.
